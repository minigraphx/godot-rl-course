01 Installation

Install the Python package with the backend of your choice.

Base Package
shell 
pip install godot-rl
Install with Backend
Stable Baselines 3
pip install godot-rl[sb3]
Sample Factory
pip install godot-rl[sf]
Ray RLLib
pip install godot-rl[rllib]
All Backends
pip install godot-rl[sb3,sf,rllib]
Download Godot Editor via CLI
shell 
gdrl.download_editor
Note: Downloads a compatible Godot 4 binary. Works on Linux, Mac and Windows.

03 Stable Baselines 3

Most common backend for Godot RL. PPO is the default algorithm and works well for most environments.

Train with Visualization
shell 
python examples/stable_baselines3_example.py \
  --env_path=examples/godot_rl_BallChase/bin/BallChase.x86_64 \
  --experiment_name=Experiment_01 \
  --viz
Train Headless
shell 
python examples/stable_baselines3_example.py \
  --env_path=examples/godot_rl_BallChase/bin/BallChase.x86_64 \
  --experiment_name=Experiment_01 \
  --speedup=8 \
  --n_parallel=4
Headless: Simply omit --viz. All training commands support headless mode this way.
Resume from Checkpoint
shell 
python examples/stable_baselines3_example.py \
  --env_path=./MyGame \
  --experiment_name=Experiment_02 \
  --resume_model_path=logs/Experiment_01/best_model.zip
SB3 Parameters
ParameterDescription
--env_pathPath to exported Godot binary required
--experiment_nameName for this run, used for saving logs and checkpoints
--vizEnable visualization window — omit for headless training
--speedupSimulation speedup factor (e.g. 8 = 8x faster than realtime)
--n_parallelNumber of parallel Godot instances to spawn
--timestepsTotal training timesteps default: 1_000_000
--onnx_export_pathExport trained model to ONNX format after training
--resume_model_pathPath to saved model zip to continue training from
--seedRandom seed for reproducibility
04 Sample Factory

Higher throughput, especially with many parallel workers. Good for scale.

shell 
gdrl --trainer=sf --env=gdrl \
  --env_path=examples/godot_rl_BallChase/bin/BallChase.x86_64 \
  --num_workers=10 \
  --experiment=BallChase \
  --speedup=8 \
  --batched_sampling=True \
  --viz
ParameterDescription
--trainer=sfSelect Sample Factory backend
--env=gdrlEnvironment name (always gdrl for Godot)
--num_workersNumber of parallel worker processes
--experimentExperiment name for checkpointing
--speedupSimulation speedup multiplier
--batched_samplingEnable batched sampling for better GPU utilization
--vizShow visualization — omit for headless

06 Editor / Debug Mode

Connect to a running Godot editor instance for interactive testing before committing to a full training run.

shell — run after pressing Play in the Godot editor 
gdrl
What this does: Steps through 1000 random actions in the running editor. Use this to verify observations, action spaces, and reward signals before training.
07 Godot Headless Flags

Godot command-line flags for running without a display.

Run Exported Binary Headless
shell 
./MyGame.x86_64 --headless
Run Godot Editor from Terminal (macOS)
shell 
/Applications/Godot.app/Contents/MacOS/Godot \
  --headless \
  --path /path/to/your/project
Godot CLI Flags Reference
FlagDescription
--headlessRun without display or rendering — fastest for training
--path <dir>Path to Godot project directory
--write-movie <file>Record gameplay to video via MovieWriter (Godot 4)
--fixed-fps <n>Lock simulation to fixed FPS — required for consistent MovieWriter output
--quit-after <n>Automatically quit after N frames
--verboseEnable verbose engine logging
--no-windowLegacy flag for windowless mode — prefer --headless in Godot 4
08 Parallel Training

Two approaches — pick based on your environment complexity and scale needs.

Option A — Multiple Agents in One Scene

Place multiple AIController nodes in a single Godot scene. All agents share one process and batch observations/actions together. Simpler to set up.

Best for: Quick setup, lower overhead, smaller environments.
Option B — Multiple Parallel Processes (SB3)
shell 
python examples/stable_baselines3_example.py \
  --env_path=./MyGame \
  --n_parallel=4 \
  --speedup=8 \
  --experiment_name=Parallel_Run
Best for: Large-scale training, better isolation between environments, more stable experience collection. Each instance communicates on a separate TCP port.
Option B — Multiple Parallel Workers (Sample Factory)
shell 
gdrl --trainer=sf --env=gdrl \
  --env_path=./MyGame \
  --num_workers=10 \
  --batched_sampling=True
09 MovieWriter

Godot 4's built-in video recorder. Works natively on macOS — no Xvfb needed.

Basic Recording (Exported Binary)
shell 
./MyGame --write-movie output.avi --fixed-fps 60 --quit-after 1800
Note: --fixed-fps is required for consistent video output. Without it frames may drop or duplicate.
Recording from Godot Editor (macOS)
shell 
/Applications/Godot.app/Contents/MacOS/Godot \
  --path /path/to/project \
  --write-movie checkpoint_100.avi \
  --fixed-fps 60 \
  --quit-after 1800
ParameterDescription
--write-movie <file>Output file path (.avi recommended)
--fixed-fps <n>Lock FPS for consistent frame timing (60 is standard)
--quit-after <n>Stop after N frames — at 60fps: 1800 = 30 seconds
10 ffmpeg

Convert and process video output from MovieWriter.

Install (macOS)
shell 
brew install ffmpeg
Convert AVI to MP4
shell 
ffmpeg -i checkpoint_100.avi -c:v libx264 -crf 23 checkpoint_100.mp4
Concatenate Checkpoint Videos
shell 
# Create a filelist.txt with one file per line:
# file 'checkpoint_100.mp4'
# file 'checkpoint_200.mp4'
# ...

ffmpeg -f concat -safe 0 -i filelist.txt -c copy training_progress.mp4
Resize / Downscale
shell 
ffmpeg -i output.avi -vf scale=1280:720 -c:v libx264 -crf 23 output_720p.mp4
11 Auto-Record Callback (SB3)

Record a video automatically every N training steps using a Stable Baselines 3 callback.

python — record_callback.py 
import subprocess
from stable_baselines3.common.callbacks import BaseCallback

class RecordCallback(BaseCallback):
    def __init__(self, record_every=100, env_path="./MyGame",
                 fps=60, duration_frames=600, verbose=0):
        super().__init__(verbose)
        self.record_every = record_every
        self.env_path = env_path
        self.fps = fps
        self.duration_frames = duration_frames

    def _on_step(self) -> bool:
        if self.n_calls % self.record_every == 0:
            outfile = f"recordings/checkpoint_{self.n_calls}.avi"
            subprocess.run([
                self.env_path,
                f"--write-movie={outfile}",
                f"--fixed-fps={self.fps}",
                f"--quit-after={self.duration_frames}",
                "--headless",
            ])
        return True

# Usage in training script:
from stable_baselines3 import PPO

model = PPO("MlpPolicy", env)
callback = RecordCallback(record_every=100, env_path="./MyGame")
model.learn(total_timesteps=1_000_000, callback=callback)
Important: To record inference (not random actions), save the current model weights before spawning the recording process, and load them inside Godot via ONNX export or a custom inference script.
12 macOS Notes
Gatekeeper — Unsigned Binaries
shell 
# Remove quarantine attribute from exported Godot binary
xattr -dr com.apple.quarantine ./MyGame.app

# Or for a raw binary:
xattr -dr com.apple.quarantine ./MyGame
  • Use Godot 4 with .NET (Mono) version if you need to run the official example environments — they require it.
  • For your own GDScript-only project, the standard (non-.NET) Godot binary is lighter and sufficient.
  • On Apple Silicon (M1/M2/M3), use the arm64 Godot binary for best performance.
  • MovieWriter works natively on macOS — no Xvfb needed (Xvfb is Linux-only).
  • If training with many headless processes, monitor thermal throttling — fan-heavy workloads can affect M-series chips.
