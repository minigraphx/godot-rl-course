CrossTheRoad & DQN

Study the official CrossTheRoad example — discrete 2D navigation with sparse rewards — then train it with DQN instead of PPO. Default workflow: exported binary, headless.

Console-first from here Units 0–2 used the editor for building and debugging. From Unit 3 on, train with an exported binary and omit --viz for speed — then run a short viz checkpoint when training finishes (see step 5).
Three ways to see your AI Godot (viz checkpoint) · TensorBoard (DQN vs Unit 2 PPO) · AIController reward tweaks
Training stalled? Check in order: (1) reward sign and scale — is “good” actually positive? (2) sparse rewards — does the agent get any signal before the goal? (3) observation bugs — are sensors updating after resets? (4) TensorBoard flat but Godot looks fine — you may need longer training or a viz checkpoint.

DQN in one page

Value-based methods learn how good each action is in each state (Q-values). DQN uses a neural network to approximate those values, with experience replay and a target network for stability.

Use DQN when the action space is discrete and rewards are sparse — like crossing lanes of traffic.

Unit 2 used PPO (policy-based). Compare learning curves in TensorBoard after this unit.

Exploration DQN explores with ε-greedy: random actions early, greedy Q-actions later. If the curve is flat, ε may be decaying too fast — check your training script’s exploration schedule. PPO explores via stochastic policy + entropy; compare Unit 2’s PPO run in TensorBoard.

Open CrossTheRoad

Clone and import
  1. From examples/CrossTheRoad, open the project in Godot .NET
  2. Enable the Godot RL Agents plugin
  3. Locate the training scene and AIController script
Export for training (recommended)

Project → Export → add macOS/Windows/Linux preset → export binary. Use that path in Python instead of Play Scene.

gdrl --env_path=./CrossTheRoad.x86_64 \
  --experiment_name=CrossTheRoad_DQN \
  --timesteps=500000 \
  --speedup=8 \
  --n_parallel=4

Adjust algorithm flags per your training script if using custom DQN entrypoint — SB3 DQN via a dedicated example script is the usual pattern.

Read the code

Trace these in order (same rhythm as SimpleReachGoal in Unit 2):

  • get_obs() — what the agent sees (position, nearby hazards)
  • get_action_space() — discrete moves (e.g. wait / up / down / forward)
  • Reward logic — sparse + penalty for crashes; note shaping vs Unit 2 dense lander rewards
  • Sync node + number of parallel env roots in the training scene

Train headless

conda activate godot_env
tensorboard --logdir=logs &

Run your DQN training command against the exported binary. Watch ep_rew_mean — sparse rewards may stay flat, then jump as the agent learns safe crossings.

5

Tweak & viz checkpoint

Viz checkpoint (~5 min)

Re-run the trained policy with --viz or Play Scene in Godot. Screenshot behavior that matches (or contradicts) the TensorBoard curve — keeps headless training from feeling invisible.

Stretch goals (pick one):

  • Increase crash penalty by 2× — does learning speed up or stall?
  • Add a small reward for forward progress — compare to pure sparse setup
  • Train the same env with PPO — which algorithm reaches reliable crossings first?
